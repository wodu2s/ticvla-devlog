주행이 되고 나니 다음 지적이 왔다. **로딩이 오래 걸린다. 추론해서 움직이는 과정도 개선이 필요하다.**

모델은 1B급이고 checkpoint는 1.9GB다. 크지 않다. 그러니 "모델이 커서 느리다"는 설명은 처음부터 의심스러웠다. 로그 타임스탬프로 첫 명령까지의 57.5초를 쪼갰다.

## 57.5초의 내역

| 구간 | 시간 | 비고 |
|---|---|---|
| 파이썬 import | 7.4s | 모델을 건드리기 전 |
| checkpoint 로드 | 3.3s | 충분히 빠르다 |
| 모델 준비 (bf16 → CUDA) | 0.8s | |
| 카메라 열기 | 0.5s | |
| **유휴 대기** | **30.0s** | 아무것도 하지 않음 |
| 첫 VLM 추론 | 14.5s | |
| 첫 명령 발행 | 1.0s | |

**가장 큰 조각이 "아무것도 안 하는 30초"다.**

원인은 단순했다. 카메라가 열리고 프레임이 준비된 뒤에도, 첫 추론이 **재해석 주기 타이머의 첫 틱까지 기다린다.** 주기가 30초니까 30초를 기다린다. 모델 크기와 아무 관계가 없다.

프레임이 모이는 즉시 1회차를 돌리게 하면 이 30초는 그냥 사라진다.

## import 7.4초 — TensorFlow가 딸려 온다

로그에 계속 이런 게 찍히고 있었다.

```
Unable to register cuDNN factory: ...
Unable to register cuFFT factory: ...
Unable to register cuBLAS factory: ...
Unable to import Axes3D (matplotlib)
```

TensorFlow와 matplotlib의 import 메시지다. 이 프로젝트는 둘 다 쓰지 않는다. `-X importtime`으로 확인했다.

| 원인 | 시간 | 누가 부르는가 |
|---|---|---|
| **tensorflow** | 2.93s | `transformers.image_transforms`가 백엔드 존재를 확인하며 통째로 import |
| torchvision | 2.07s | 모델 모듈 |
| torch | 1.60s | 필수 |
| sklearn | 0.96s | `transformers.generation.candidate_generator` |
| matplotlib | — | 학습·평가용 파일이 런타임에 딸려 옴 |

`transformers`는 설치된 백엔드를 자동 탐색한다. TensorFlow가 시스템에 깔려 있으면 쓰지 않아도 import한다. 환경변수 하나로 막을 수 있다.

```
import ticvla                              9.22s
USE_TF=0 로 import                          6.47s     ← 2.75초 절감, 코드 수정 없음
```

## 추론 23.4초의 성질

Action Expert는 11.9ms다. 나머지 전부가 VLM 토큰 생성이다.

```
200 토큰 / 23.4초 = 토큰당 약 117ms
```

**출력 길이가 곧 지연이다.** 현재 `<think>`는 60~70단어로 길다.

다만 무작정 줄일 수는 없다. 토큰 상한을 131 미만으로 내리면 `<answer>`가 잘려 waypoint 파싱이 깨진다. 그리고 더 중요한 제약이 있다 — **`<think>`는 KV 캐시를 통해 Action Expert의 입력이 된다.** 짧아지면 궤적 품질 자체가 바뀔 수 있다. 그래서 이 변경은 같은 장면 A/B 없이는 적용할 수 없다.

## 개선 계획

| 항목 | 현재 | 목표 | 방법 | 위험 |
|---|---|---|---|---|
| 첫 사이클 유휴 대기 | 30.0s | ~0s | 프레임 준비 즉시 1회차 실행 | 낮음 |
| import | 9.2s | ~5s | `USE_TF=0` + matplotlib 지연 import | 낮음 |
| VLM 추론 | 23.4s | ~16s | 토큰 상한 200 → 140 | 중간 |
| VLM 추론 (추가) | | 10초대 | `<think>` 길이 제한 프롬프트 | 중간~높음 |
| 양자화 | | 2~3배 | INT8 / W4A16 | 높음, 데모 이후 |
| **첫 명령까지** | **57.5s** | **~22s** | | |

그리고 가장 실용적인 답이 하나 더 있다. **시연에서는 프로세스를 재시작하지 않는 것이다.** 브리지를 상주시키고 enable 토픽으로 켜고 끄면 로딩 시간은 0초다.
