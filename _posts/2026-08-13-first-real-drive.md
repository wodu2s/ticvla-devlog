Shadow 모드에서는 로봇이 움직이지 않는다. 명령을 계산하되 발행하지 않는다. 여기까지의 모든 검증이 그 모드에서 이루어졌고, 이제 실제로 바퀴를 돌릴 차례였다.

## 순서를 지킨다

바로 바닥에 내려놓지 않았다.

1. 로봇을 박스 위에 올려 **세 바퀴를 공중에 띄운다**
2. 모델 없이 **손으로 명령을 쏴서** 배선과 방향을 확인한다
3. 모델을 붙인다 (여전히 바퀴는 떠 있다)
4. 그다음에 바닥

2번이 특히 중요했다. 모델을 붙인 상태에서 문제가 생기면 원인이 모델인지 배선인지 알 수 없다. 손으로 전진·좌회전·후진 명령을 각각 쏴서 먼저 계층을 검증했다.

## 안전 검증 4/4

| 항목 | 결과 | 근거 로그 |
|---|---|---|
| 회전 방향 | PASS | 수동 명령으로 전진·좌회전 정상 |
| 후진 클램프 | **PASS** | `후진 차단 — vx=-0.018 → 0` |
| 비상정지 | PASS | 수신 즉시 0 고정, 래치 유지 |
| 강제종료 정지 | PASS | 발행 끊고 0.5초 내 정지 |

후진 클램프는 오랫동안 "코드에는 있는데 실제로 도는 걸 본 적 없는" 항목이었다. 클램프가 명령 발행 지점에 있어서 **Shadow 모드에서는 아예 실행되지 않기** 때문이다. 이번에 처음으로 실제 차단 로그를 봤다.

## 바퀴가 절대 돌 수 없는 설정

모델을 붙이고 돌렸더니 브리지가 스스로 경고를 뱉었다.

```
max_speed(0.080) 가 데드존(0.095) 보다 작다.
이 설정으로는 바퀴가 절대 돌지 않는다.
```

초기 문서에 "실차 초기값 0.08"이라고 적어뒀던 값을 그대로 쓴 결과다. 그 숫자는 데드존을 측정하기 **전에** 적은 것이었다. 상한을 하한보다 낮게 잡아놨으니 모든 명령이 0이 된다.

상한을 0.10으로 올렸다. 그런데 여전히 거의 안 움직였다.

```
관측 속도: 0.0796 / 0.0942 / 0.0286  →  전부 데드존 미만 → 0
```

구조를 보면 당연했다.

```
데드존 0.095  ≤  실효 구간  ≤  관문 상한 0.10      폭 0.005
```

**실효 속도 창이 0.005 m/s밖에 없다.** 그리고 여기서 한 번 더 헛짚었다. "상한을 더 올리면 되겠지" 했는데, 상한은 **cap이라 작은 값을 키우지 않는다.** 0.0796은 상한을 아무리 올려도 0.0796이다.

답은 데드존 정책이었다. 데드존 미만 명령을 0으로 죽이는 대신 **최소 유효속도로 끌어올리는** boost 정책으로 바꾸자 바로 굴러갔다.

```
명령 상태 전이: init -> ok (vx=+0.065, vy=-0.069)     합성 0.095
```

## 그리고 바닥

열린 복도에서 240초를 돌렸다. 사람이 앞에 서 있는 상태로 출발했다.

**① 인식** — 3사이클 모두 사람을 짚었다.

> "The critical object is the person ahead-center. They seem stationary and may remain in place."

**② 회피** — 출력 waypoint의 횡방향 성분이 사이클마다 갱신됐다. (+가 왼쪽)

| 사이클 | y @3s / @6s / @9s | 같은 사이클의 `<think>` |
|---|---|---|
| #1 | −0.13 / −0.24 / −0.44 | "slightly right, slow and yield" |
| #2 | +0.08 / −0.02 / +0.01 | "slight left bias, keep clearance" |
| #3 | **+0.49 / +2.39 / +4.95** | "ease left to recenter" |

좌우 중 어느 쪽으로 피할지는 상황마다 달랐지만, **서술과 부호가 한 번도 어긋나지 않았다.** 말과 숫자가 따로 놀지 않는다는 것 — 이게 이 시스템에서 가장 보여줄 만한 부분이다.

**③ 정지** — 예측 변위가 내려가면서 도착 판정이 걸렸다.

```
2.793 → 0.389 → 0.349 → 0.322 → 0.311 → 0.324 → 0.287 → 0.286
→ t+78.5초, 변위 0.2945에서 ARRIVED, 래치 ON
```

주행 중 변위는 2.2~3.2 대였고 임계값은 0.30이었다. **실차에서 정확히 분리됐다.**

그리고 래치를 켜둔 판단이 여기서 증명됐다. 도착 후 변위가 다시 0.88까지 올라갔다. 장면은 그대로인데 새 `<think>`가 생성되면서 KV 캐시가 바뀌고 궤적 스케일이 흔들린 것이다. 래치가 없었으면 멈췄다가 다시 출발했을 것이다.
