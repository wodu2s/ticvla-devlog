빠른 루프가 돌기 시작하면 다음 질문은 하나다. **이 숫자를 모터에 넣어도 되는가.**

두 가지를 먼저 확인해야 했다. 좌표계 부호와 안전 계층이다.

## 좌표계 — y가 왼쪽인가 오른쪽인가

부호 하나가 뒤집혀 있으면 회피 로직이 정확히 반대로 작동한다. 사람을 피하라고 만든 시스템이 사람 쪽으로 간다.

프롬프트에 좌표계가 명시되어 있었다.

```
"where x is positive for forward, y is positive for left,
 and theta is the heading angle in radians."
```

REP-103 표준과 같다. 문서를 믿지 않고 네 장면으로 실측했다.

| 장면 | 기대 | 결과 |
|---|---|---|
| 복도 정면 | x↑, y≈0, yaw≈0 | 통과 (4관측) |
| 벽 정면 | y·yaw 동일 부호 | 통과 |
| 좌측만 열림 | y>0, yaw>0 | 통과 |
| 우측만 열림 | y<0, yaw<0 | 통과 (2사이클 재현) |

좌우 뒤집힘은 없었다.

다만 판정 근거는 `<answer>` **텍스트**였다. 텍스트가 0 근처인 애매한 상황에서 실제 제어에 쓰이는 텐서 궤적의 초반이 반대로 나오는 경우를 봤다(`vx = -0.106`, `-0.114`). 그래서 **후진 클램프**를 넣었다. 카메라가 앞만 보는 로봇에게 후진은 곧 시야 밖으로 움직이는 것이다.

## 텍스트와 텐서는 다른 경로다

이 과정에서 헷갈리기 쉬운 지점을 하나 정리했다.

`<answer>`의 좌표는 3초 / 6초 / 9초 시점의 **누적 변위(미터)**다. 반면 실제 제어에 쓰이는 값은 Action Expert가 내는 **텐서**다. 둘은 다른 경로로 나온다.

근거는 명확했다. `<answer>`가 `(0,0,0)`인데 브리지 내부 속도는 0.0519 m/s였다. 텍스트로는 4.19m/3초 = 1.4 m/s(보행 속도)인데 텐서는 0.03~0.09 m/s다.

**로그를 읽을 때 이 둘을 섞으면 잘못된 결론에 도달한다.** 실제로 "좌표 단위가 25배 이상하다"는 가설을 세웠다가 폐기했다.

## 안전 관문 — 없어서 만들었다

모터 제어 노드의 콜백을 읽다가 발견했다.

```
cmd_vel_callback 에 명령 타임아웃이 없다.
메시지가 끊기면 마지막 wheel_vec 을 그대로 유지한다.
```

즉 **상위 노드가 강제 종료되면 로봇은 마지막 속도로 계속 달린다.** 정상 종료 경로에는 정지 처리가 있지만, `kill -9`나 크래시는 거기로 가지 않는다.

기존 파일을 고치는 대신 앞단에 관문 노드를 새로 만들었다. 우선순위는 이렇다.

```
비상정지(래치) > 조이스틱 > 비활성화 > 명령 타임아웃 > 정상 통과
```

6개 케이스를 만들어 전부 통과시켰다.

| 케이스 | 기대 | 결과 |
|---|---|---|
| 정상 통과 | 값 그대로 | PASS |
| 상위 끊김 0.5s | 전부 0 (핵심) | PASS |
| 후진 명령 | vx = 0 | PASS |
| 상한 초과 | 상한으로 클램프 | PASS |
| 비상정지 | 명령 있어도 0 | PASS |
| 조이스틱 | 조이스틱 우선 | PASS |

입력이 하나도 없을 때 출력 토픽이 20.000Hz(표준편차 0.00013)로 유지되는 것도 확인했다. 타이머 기반으로 계속 0을 쏘는 구조라 "명령이 없으면 정지"가 보장된다.
